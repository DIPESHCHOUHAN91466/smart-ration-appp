# Staging checklist — public demo on synthetic data

Staging is what `render.yaml` deploys: the Python backend (which also serves the website) as one Docker
web service, and a managed MySQL 8 with TLS. The C# API is retired (2026-10-02). Every person, card and Aadhaar value in it is
synthetic. Step-by-step guide: [../../docs/deployment/RENDER.md](../../docs/deployment/RENDER.md).
Settings: [staging.env.example](staging.env.example).

## Before the first deploy

- [ ] Managed MySQL 8 created (TLS on); an empty `smartration` database; its CA certificate downloaded.
- [ ] `DATABASE_URL`, `MYSQL_SSL_CA` typed into the hosting dashboard only (never a file in git).
- [ ] `JWT_SECRET_KEY` and `QR_SECRET` generated by the host (Render: `generateValue`), not reused from development.
- [ ] `SEED_DEMO_PASSWORD` set if the demo accounts should be able to sign in.
- [ ] Locally green: `.\sr.ps1 test -MySql` and both images build (`.\scripts\deployment\build-images.ps1`).

## After every deploy

- [ ] The service reports healthy in the dashboard (health check path `/health/live`); `/ready` shows `legacyApi: disabled`.
- [ ] Smoke test passes against the public URL:
      `backend\SmartRation\.venv\Scripts\python -m pytest tests\smoke --base-url https://<your-app>.onrender.com`
- [ ] `/ready` shows `database: ok`, `migrations: ok`, `legacyApi: ok`.
- [ ] Integrity checks (read-only) from a machine allowed to reach the database:
      `DATABASE_URL=<staging url> python scripts/check_data_integrity.py`.
- [ ] Signing in with a demo account and booking a slot works in the browser.

## Known limits (free plan)

- Services sleep after inactivity; the first request can take about a minute (not an error).
- OTP SMS are **not delivered** (`Sms__AllowMockOutsideDevelopment=true`, synthetic data only).
- The AI analytics service is not deployed; AI panels show their "not available" state.
