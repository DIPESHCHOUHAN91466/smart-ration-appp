# Deploy to Render (public demo link)

This puts Smart Ration on the internet as a **synthetic-data demo** at an address like
`https://smart-ration-hsd2c.onrender.com`. It uses the Blueprint in [`render.yaml`](../../render.yaml).
Nothing here uses real citizen data (`DATA_MODE=synthetic`; real mode refuses to start).

| Part | Where | Cost |
|---|---|---|
| Website + Python API (`smart-ration-hsd2c`) — **the link you share** | Render web service (Docker) | Free plan |
| C# business API (`smart-ration-hsd2c-core`) | Render web service (Docker) | Free plan |
| MySQL 8 database | Aiven (Render has no MySQL) | Free plan |

What was verified before this guide was written (2026-09-25, locally with Docker): both images build;
started together against an **empty** MySQL 8 that **requires TLS**, the C# API created the schema and the
demo data, the Python service waited, verified and adopted it, `/ready` = ready, both connected encrypted
(TLS 1.3); a restart changed nothing; the Playwright end-to-end suite passed against it (8 passed, the
developer status page is correctly hidden in production). **Not verified:** Render itself and Aiven —
this is the first real deployment, so follow the checks in step 5.

## 1. Create the MySQL database (Aiven, about 5 minutes)

1. Sign up at https://aiven.io and create a service: **MySQL**, plan **Free**.
2. When it is *Running*, open it → **Overview** → *Connection information*. Note **Host**, **Port**,
   **User** (`avnadmin`), **Password** and **Database** (`defaultdb`).
3. On the same page, download or show the **CA certificate** and copy its whole text, including the
   `-----BEGIN CERTIFICATE-----` and `-----END CERTIFICATE-----` lines.
4. Build your `DATABASE_URL` from those values (one line, no spaces):

   ```
   mysql+pymysql://avnadmin:PASSWORD@HOST:PORT/defaultdb?charset=utf8mb4&ssl_ca=/tmp/mysql-ca.pem
   ```
   If the password contains `@ : / ? # %`, replace them with `%40 %3A %2F %3F %23 %25`.
   Keep this line private; it contains the password.

## 2. Make sure the code is on GitHub

Render deploys from your repository `DIPESHCHOUHAN91466/smart-ration-appp` (branch `main`), and it must
contain `render.yaml` and the two Dockerfiles. Push your latest commits first (`git push origin main`).

## 3. Create the Blueprint on Render

1. Sign up at https://render.com (you can sign in with GitHub) and allow access to the repository.
2. **New → Blueprint** → choose `smart-ration-appp` → Render reads `render.yaml` and lists the two services
   and the `smart-ration-shared` environment group.
3. It asks for the values marked `sync: false`:
   - `DATABASE_URL` → the line from step 1.4
   - `MYSQL_SSL_CA` → the certificate text from step 1.3
   (`JWT_SECRET_KEY` and `Qr__Secret` are generated by Render — you never see or type them. This is also
   a fresh key, unrelated to the old one in git history.)
4. **Apply**. Render builds both images (the first build takes 5–10 minutes).

## 4. First start (what happens, in order)

1. `smart-ration-hsd2c-core` (C#) connects over TLS, creates the 25 tables and the synthetic demo data,
   and logs `SYNTHETIC DEMO: ... OTP messages are NOT delivered to anyone.`
2. `smart-ration-hsd2c` (Python) logs `wait-for: ... not ready yet` until the C# API answers, then
   `Existing schema (created by the C# API) matches the models exactly. Adopting it`, then starts.

## 5. Check it and get the link

Open the **smart-ration-hsd2c** service in Render; its URL at the top is **your deployment link**.

| Check | Expected |
|---|---|
| `https://<your-link>/` | the Ration Mitra landing page |
| `https://<your-link>/ready` | `{"ready":true, ... "legacyApi":"ok"}` |
| `https://<your-link>/health` | `"status":"healthy"` (`aiService: disabled` is expected) |
| Ask the chatbot "which documents do I need?" | an answer in the chat window |

Demo accounts (synthetic): the login page offers them (`VITE_DEMO_MODE=true`). **Anyone who has the link
can use them**, including the government dashboard — fine for synthetic data, but don't put real data in.
Set `VITE_DEMO_MODE=false` on `smart-ration-hsd2c` and redeploy to hide them.

## Good to know (free plan)

- A free service **sleeps after 15 minutes** without visitors; the next visit waits about a minute. The
  C# service wakes separately, so the first dashboard request after a long pause can fail once — reload.
- Render gives 750 free instance hours per month for all free services together; sleeping doesn't count.
- The C# API's rate limits for OTP (6/min) and QR scans (120/min) are shared by all demo users, because
  every request reaches it through the Python service.
- OTP messages are not sent (no SMS gateway: *BLOCKED — requires external integration*).
- The optional AI analytics service is not deployed; its panels show "unavailable".

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| C# build/deploy fails with `Sms:Provider must be 'Http'` | the opt-in variable is missing | `Sms__AllowMockOutsideDevelopment=true` on `smart-ration-hsd2c-core` (DATA_MODE must be synthetic) |
| Logs show `Access denied` or `SSL` errors | wrong password in `DATABASE_URL`, or `MYSQL_SSL_CA` incomplete | re-copy both from Aiven (whole certificate, both BEGIN/END lines) |
| Python logs `wait-for: WAIT_FOR_LEGACY_API=true but LEGACY_API_URL is empty` | Render didn't copy the C# host name | set `LEGACY_API_URL` on `smart-ration-hsd2c` to `smart-ration-hsd2c-core.onrender.com` (your C# service's address) |
| Python logs `Refusing: partial or unknown schema` | the database already had other tables | use an empty database |
| Pages load, dashboard calls fail with 502/504 once | the C# service was asleep | reload after a minute |
| A service name was taken, so Render added a suffix | — | nothing to change: the services find each other by Render's own references |

Local verification of the same setup: `.\sr.ps1 docker` builds the image; this guide's first-start
sequence is what `deployment/docker/docker-compose.yml` does too (with a local MySQL).
