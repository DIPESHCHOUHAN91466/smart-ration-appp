# Deploy to Render (public demo link)

This puts Smart Ration on the internet as a **synthetic-data demo** at an address like
`https://smart-ration-hsd2c.onrender.com`. It uses the Blueprint in [`render.yaml`](../../render.yaml).
Nothing here uses real citizen data (`DATA_MODE=synthetic`; real mode refuses to start).

| Part | Where | Cost |
|---|---|---|
| Website + Python API (`smart-ration-hsd2c`), **the link you share** | Render web service (Docker) | Free plan |
| MySQL 8 database | Aiven (Render has no MySQL) | Free plan |

The old C# API is retired (2026-10-02): every route is served by the Python backend, which also creates the
schema (Alembic migrations) and the demo data on the first start.

Verified before this version of the guide (2026-10-02, locally): the first start on an **empty** database
(`setup_database.py --seed` with `SEED_DEMO_PASSWORD`) creates every table and the demo accounts, and the demo
citizen can then sign in, open their ration card, book a slot and get the signed QR through the real API
(`tests/integration/test_db_scripts.py::test_first_boot_demo_citizen_can_sign_in_see_their_card_and_book`);
the blueprint's settings pass the production start-up checks. **Not verified yet:** Render and Aiven
themselves; follow the checks in step 5.

## At a glance: everything to create

**Order:** (1) Aiven MySQL + a `smartration` database → (2) code on GitHub with CI green → (3) Render Blueprint →
(4) first deploy creates the schema and demo data → (5) checks below.

| Where | What | Notes |
|---|---|---|
| Aiven | MySQL service, plan Free | TLS is required by Aiven; keep it on |
| Aiven | database `smartration` | the setup script refuses any other name |
| Render | Blueprint from `render.yaml` | creates the web service `smart-ration-hsd2c` (Docker, Free, Singapore) |
| Render | nothing else | no build or start command to type: Render builds `backend/SmartRation/Dockerfile`; the image's entrypoint (`docker-entrypoint.sh`) prepares the database, then runs `uvicorn app.main:create_app --factory` on port 8000; health check `/health/live` |

Environment variables of `smart-ration-hsd2c` (all defined by `render.yaml`; you only type the three marked *you*):

| Variable | Value | Secret | Set by |
|---|---|---|---|
| `DATABASE_URL` | `mysql+pymysql://avnadmin:<password>@<host>:<port>/smartration?charset=utf8mb4&ssl_ca=/tmp/mysql-ca.pem` | yes | **you** (Blueprint prompt) |
| `MYSQL_SSL_CA` | Aiven's CA certificate, whole PEM text | no (public CA), but keep it with the URL | **you** |
| `SEED_DEMO_PASSWORD` | password of the 3 synthetic demo accounts, 8+ characters | yes | **you** |
| `JWT_SECRET_KEY` | random | yes | Render (`generateValue`) |
| `QR_SECRET` | random; **never change after the first deploy** | yes | Render (`generateValue`) |
| `ENVIRONMENT` | `production` | no | `render.yaml` |
| `DATA_MODE` | `synthetic` | no | `render.yaml` |
| `DEMO_OTP_ENABLED` | `false` | no | `render.yaml` |
| `SMS_ALLOW_MOCK_OUTSIDE_DEVELOPMENT` | `true` (synthetic demo only; OTP SMS not sent) | no | `render.yaml` |
| `LEGACY_API_URL`, `AI_SERVICE_URL` | empty (retired C# API; AI analytics not deployed) | no | `render.yaml` |
| `RUN_DB_SETUP`, `RUN_DB_SEED` | `true` (migrations every start; demo data only into empty tables) | no | `render.yaml` |
| `VITE_DEMO_MODE` | `true` (build time: the login page lists the demo accounts) | no | `render.yaml` |

Secrets are only ever typed into Render's dashboard or generated by Render: never in a file, never in git, never
in CI (CI uses visibly fake values). The app never logs them, and prints database URLs with the password hidden.

The CI job "First boot like Render" runs this same image with these same non-secret values against an empty MySQL 8
(migrations, seed, readiness, website, demo citizen sign-in, restart), and `tests/regression/test_deploy_config.py`
fails if `render.yaml` and that job ever differ. Render deploys a push only after CI passes (`autoDeployTrigger:
checksPass`).

## 1. Create the MySQL database (Aiven, about 5 minutes)

1. Sign up at https://aiven.io and create a service: **MySQL**, plan **Free**.
2. When it is *Running*, open **Databases** and create a database named **`smartration`**
   (the setup script refuses any other name, so it can never write to the wrong database).
3. Open **Overview** → *Connection information*. Note **Host**, **Port**, **User** (`avnadmin`) and **Password**.
4. On the same page, download or show the **CA certificate** and copy its whole text, including the
   `-----BEGIN CERTIFICATE-----` and `-----END CERTIFICATE-----` lines.
5. Build your `DATABASE_URL` (one line, no spaces):

   ```
   mysql+pymysql://avnadmin:PASSWORD@HOST:PORT/smartration?charset=utf8mb4&ssl_ca=/tmp/mysql-ca.pem
   ```
   If the password contains `@ : / ? # %`, replace them with `%40 %3A %2F %3F %23 %25`.
   Keep this line private; it contains the password.

## 2. Make sure the code is on GitHub

Render deploys from `DIPESHCHOUHAN91466/smart-ration-appp` (branch `main`), which must contain `render.yaml`
and `backend/SmartRation/Dockerfile`. Push your latest commits first (`git push origin main`).

## 3. Create the Blueprint on Render

1. Sign up at https://render.com (you can sign in with GitHub) and allow access to the repository.
2. **New → Blueprint** → choose `smart-ration-appp`. Render reads `render.yaml` and lists one service.
3. It asks for the values marked `sync: false`:
   - `DATABASE_URL`: the line from step 1.5
   - `MYSQL_SSL_CA`: the certificate text from step 1.4
   - `SEED_DEMO_PASSWORD`: the password for the three demo accounts (your choice, at least 8 characters).
     Anyone you give it to can sign in as the demo citizen, shop owner and **government official**.
   (`JWT_SECRET_KEY` and `QR_SECRET` are generated by Render: you never see or type them. Never change
   `QR_SECRET` afterwards; it would invalidate every QR code already issued.)
4. **Apply**. Render builds the image (the first build takes 5–10 minutes).

If you created the Blueprint from an older version of this file, Render may still have the
`smart-ration-hsd2c-core` (C#) service: suspend or delete it in the Dashboard after the new deploy is healthy.

## 4. First start (what happens, in order)

1. The container connects to MySQL over TLS and runs `setup_database.py --seed`: `Empty database` →
   migrations create every table → synthetic reference data, slots and the three demo accounts are loaded →
   `DATABASE VERIFICATION PASSED`.
2. The API starts. Later deploys only apply new migrations; existing data is never dropped.

## 5. Check it and get the link

Open the **smart-ration-hsd2c** service in Render; its URL at the top is **your deployment link**.

| Check | Expected |
|---|---|
| `https://<your-link>/` | the Ration Mitra landing page |
| `https://<your-link>/ready` | `{"ready":true, ... "legacyApi":"disabled"}` |
| `https://<your-link>/health` | `"status":"healthy"` (`aiService` and `legacyApi`: `disabled`) |
| Smoke tests from this PC | `SMOKE_BASE_URL=https://<your-link> python -m pytest tests/smoke` all pass |
| Sign in as `rural@example.com` with your demo password | the citizen dashboard with a ration card |

Demo accounts (synthetic): `rural@example.com`, `shop@example.com`, `officer@example.com`, all with
`SEED_DEMO_PASSWORD`. The login page offers them (`VITE_DEMO_MODE=true`). Set `VITE_DEMO_MODE=false` and
redeploy to hide them.

**Android app:** build it against the link (see `smart_ration_mobile/RELEASE.md`):
`flutter build apk --release --dart-define=APP_ENV=staging --dart-define=API_BASE_URL=https://<your-link>`.

## Good to know (free plan)

- A free service **sleeps after 15 minutes** without visitors; the next visit waits about a minute.
- Sign-in codes (OTP) are **not sent** (no SMS gateway: `SMS_ALLOW_MOCK_OUTSIDE_DEVELOPMENT=true` for this
  synthetic demo only). Use email + password sign-in.
- The optional AI analytics service is not deployed; its panels show "unavailable". The AI assistant and
  help chat work (they run inside the Python service).

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Logs show `Refusing: DATABASE_URL points at 'defaultdb', expected 'smartration'` | the URL uses Aiven's default database | create the `smartration` database (step 1.2) and use it in `DATABASE_URL` |
| Logs show `Access denied` or `SSL` errors | wrong password in `DATABASE_URL`, or `MYSQL_SSL_CA` incomplete | re-copy both from Aiven (whole certificate, both BEGIN/END lines) |
| Logs show `DEMO_OTP_ENABLED must be false` or `SMS_PROVIDER must be 'http'` | an environment variable was changed in the Dashboard | restore the values from `render.yaml` |
| Logs show `Refusing: partial or unknown schema` | the database already had other tables | use an empty `smartration` database |
| `NOTE: no users created` in the logs | `SEED_DEMO_PASSWORD` was empty on the first start | set it, then run `python scripts/seed_database.py` from the service's Shell (users are only added to an empty Users table) |

Local verification of the same setup: `.\sr.ps1 docker` builds the image; `deployment/docker/docker-compose.yml`
runs it with a local MySQL.
